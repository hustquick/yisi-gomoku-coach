# 三端架构

## 共同数据流

```text
棋盘操作
  → 共享局面模型
  → 分析任务控制器（取消旧局面）
  → Rapfi 适配器
  → 候选着、评分、主变化
  → 教练评价 / 箭头动画 / 局势图
```

## 平台实现

### HTML

- React + TypeScript 绘制响应式 15×15 棋盘。
- 优先使用 Rapfi WebAssembly + Web Worker，避免阻塞界面。
- 开发期保留本地原生 Rapfi 服务作为性能和结果基准。
- 网络权重与配置作为静态资源缓存，安装为 PWA 后可离线使用。

### iOS

- SwiftUI 界面，Observable 状态控制器。
- Rapfi C++17 编译为 arm64 静态目标，经 Objective-C++ 桥接。
- 分析运行在独立任务中；新落子、悔棋、切换规则或深度会取消旧任务。
- 权重、配置、许可和源码地址随 App Bundle 分发。

### Android

- Kotlin / Java UI 与自定义棋盘 View。
- Rapfi C++17 通过 CMake + JNI 编译为 arm64-v8a 原生库。
- 引擎线程与 UI 线程隔离；使用任务代号丢弃过期结果。
- 权重首次启动复制到应用私有目录，之后完全离线。

## 规则层

第一阶段支持自由五子棋；第二阶段加入标准连珠禁手判定。规则层必须独立于 Rapfi，避免仅依赖引擎输出判断落子是否合法。

## 教练评价

教练文本必须由 Rapfi 的走前评分、走后评分、候选排名和主变化生成，不使用与局面无关的固定套话。若引擎超时，明确显示“未评分”，不产生猜测性分数。
